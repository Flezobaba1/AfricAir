## TypeScript and Vite build

The build command runs `tsc -b` and then `vite build`.

`tsc -b` runs the TypeScript build/type-check using the project’s TypeScript configuration. It checks that the TypeScript code is valid.

`vite build` bundles the frontend application, optimises it for production, and produces the deployable files in `dist/`.

`vite build` is the command that creates files in `dist/`.



## Vite chunks

`manualChunks` tells Vite/Rollup to put certain dependencies into separate JavaScript files instead of one large application bundle:

- PDF-related libraries (`jspdf`, `html2canvas`, and `dompurify`) become the `pdf` chunk.
- `airports.json` becomes the `airports` chunk.
- React becomes the `react` chunk.

This allows these files to be cached independently and means a browser does not necessarily need to download every feature immediately.

`chunkSizeWarningLimit: 700` sets Vite’s warning threshold to 700 kB. Vite warns when a generated JavaScript chunk is larger than this limit. The limit was increased because the PDF library is intentionally large and placed in its own chunk.

The largest chunk is `dist/assets/pdf-o1MWN_TF.js`, at 584,775 bytes. This matters on a 3G connection because downloading a large JavaScript file is slow and delays the feature or page becoming usable. Keeping it separate allows the browser to cache it and, ideally, load it only when the PDF feature is needed.


## Lockfile

Commands run:

`Copy-Item .\pnpm-lock.yaml .\pnpm-lock.yaml.original`

`Remove-Item .\pnpm-lock.yaml`

`pnpm install`

`Compare-Object (Get-Content .\pnpm-lock.yaml.original) (Get-Content .\pnpm-lock.yaml)`

After deleting the lockfile, `pnpm install` generated a new `pnpm-lock.yaml`. In this run, comparing the new and original files produced no output, so pnpm resolved the same dependency versions.

`--frozen-lockfile` is important because it requires the lockfile to match the project configuration and installs the exact locked dependency versions. Without it, dependency resolution can change as newer compatible package versions are published. That makes CI builds less reproducible: a build that worked yesterday can fail or behave differently today without any source-code change.


## Why `pnpm dev` must not serve production traffic

`pnpm dev` must never be used for production traffic because:

1. It runs Vite’s development server, which is intended for local development rather than reliable public hosting.
2. It serves development behaviour such as hot-module replacement and on-demand transforms, rather than the optimised static files generated by `pnpm build`.
3. It is not a production web server: it does not provide the normal production controls provided by nginx, such as TLS termination, stable static-file serving, access controls, and a safe deployment/rollback setup.
